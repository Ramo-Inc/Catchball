## 3. 仕様書から変えた点

| # | 仕様書 | 今の実装 | 理由・決めた人 |
|---|---|---|---|
| 1 | 通信の基盤は 127.0.0.1 に限る（§9） | AI 用・管理用の API は 127.0.0.1 のまま。**WebUI（閲覧専用）だけ**を LAN の 47822 にも公開する（既定で有効） | 別の PC から見守りたいというユーザーの要望（2026-10-31）。D-011 |
| 2 | AI ごとに別の資格情報（§9） | 参加者ごとのトークンは今も別々。加えて、**参加用キー**（PC・ユーザーごとに1つ）で、会話の中から参加できる | 起動をふつうの MCP の使い方に合わせるため（ユーザーの要望）。同じ OS ユーザーならトークンファイルも読めるので、守れる範囲は実質的に変わらない。D-012 |
| 3 | 技術構成は TypeScript＋MCP SDK＋SQLite（§7） | SQLite は Node 組み込みの `node:sqlite` | ネイティブ部品が要らず、Windows でのインストールの失敗を避けられる。D-009 |
| 4 | 未取得が残れば、間隔を空けて再通知（§8） | Claude は 5 分・15 分・30 分で再通知。**Codex は時間では再通知しない** | Codex の queue は保存されて必ず処理されるので、重ねると余分なターンになる（実機で確認）。D-007 |
| 5 | 運用指示を AI に渡す（§要件） | MCP の instructions に加え、通知文にも最小限の手順を入れる | Codex が MCP の instructions だけでは返信しなかった（PoC）。D-008 |
| 6 | 承認待ちを検知して通知を保留（§8・§9） | 保留する仕組みはあるが、検知（Hooks 連携）が未実装なので、常に「不明」 | 未実装（ROADMAP） |
| 7 | 遠隔 PC・クラウド公開は対象外（§13） | 対象外のまま（WebUI の閲覧だけは LAN に公開） | — |
| 8 | `channel_ack` で取得を記録する。取得後に落ちたら再取得され得る（§8・§11） | `channel_ack` をなくし、`channel_receive` で本文を返した時点で取得済みにする。同じメッセージは二度返らない | 受信のたびに ACK の呼び出しが要り、手間が多いため（ユーザーの判断、2026-11-02）。受け取った直後にセッションが落ちたときの取り直しはできなくなる。D-016 |
