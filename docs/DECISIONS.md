# 設計判断の記録

新しい判断をしたら、下に追記します。番号は振り直しません。判断を覆したときは、元の項目は消さずに「→ D-xxx で変更」と書き足します。

|---|---|---|---|
| D-001 | 2026-10-30 | AI からは MCP ツール、人からは WebUI を使う。どちらも同じブローカーの同じデータを見る | 仕様書 §1。画面の操作に頼る連携は採らない |
| D-002 | 2026-10-30 | 通知では「未取得がある」ことだけを伝え、本文は DB を正として `channel_receive` で取りに来させる | 仕様書 §8。Claude の Channel には ACK がなく、届かなかった通知は黙って捨てられるため、本文を通知に載せない |
| D-003 | 2026-10-30 | Codex への通知は `codex queue`、Claude への通知は Channel（`notifications/claude/channel`）で行う。→ D-020 で、Pi は Channel の代わりに Pi 拡張機能の受け口に書く | 仕様書 §10。PoC で、実物の CLI で動くことを確認（[記録](verification/poc-20261031.md)） |
| D-004 | 2026-10-30 | 承認をメッセージで中継しない（`claude/channel/permission` を宣言しない） | 仕様書 §9。PoC で、メッセージでは承認されないことを確認（I3） |
| D-005 | 2026-10-31 | 本実装の前に PoC で受信経路を確かめ、合格してから本実装に入る | 受信経路が動かなければ設計を作り直すことになるため（ユーザーの提案）。G1〜G5 すべて合格 |
| D-006 | 2026-10-31 | 受信済み・ACK 待ちのメッセージでは、もう一度通知しない | PoC で余分な通知と空のターンが出たため。→ D-016 で ACK の操作がなくなり、「受信済み・ACK 待ち」の状態もなくなった |
| D-007 | 2026-10-31 | Codex には時間ごとの再通知をしない。Claude は 5 分・15 分・30 分 | queue は Codex 側に保存され、アイドルになれば1件につき1ターン処理される。重ねると余分なターンになる（実機で確認）。→ 2026-11-02 に補足：通知そのものが失敗したときは、Codex・Claude とも間隔を空けて送り直す（D-019） |
| D-008 | 2026-10-31 | 通知文に、受信・ACK・返信の最小限の手順を入れる（→ D-016 で ACK はなくなり、今は受信・返信の手順） | Codex では MCP の instructions がツールの説明としてしか渡らず、PoC で依頼に返信しなかった。通知文に入れたら返信した |
| D-009 | 2026-10-31 | SQLite は Node 組み込みの `node:sqlite` を使う | ネイティブ部品が不要で、Windows でのインストール失敗を避けられる |
| D-010 | 2026-10-31 | 接続状態（最後のハートビート）はメモリで管理し、状態が変わったときだけ DB に書く | 5 秒ごとの書き込み（fsync）を避けるため。ブローカーを再起動すると全員 offline から始まる |
| D-011 | 2026-10-31 | WebUI（閲覧専用）を LAN の 47822 にも公開する（既定で有効）。AI 用・管理用の API は 127.0.0.1 のみ | 別の PC から見守りたいというユーザーの要望。閲覧に必要な API 以外は LAN 側に置かない |
| D-012 | 2026-10-31 | 会話の中で `channel_join` を呼ぶだけで参加できるようにする（参加用キー）。トークンファイルの方法も残す（→ D-017 で ID の指定が必須に、D-018 でルームの指定も必須になった） | ユーザーの要望：「ふつうの MCP として登録し、引数を付けて起動すればいい」。専用の起動コマンドは作らない |
| D-013 | 2026-10-31 | Codex の会話 ID は、AI が `$CODEX_THREAD_ID` を調べて `channel_join` で渡す | Codex は MCP サーバーに会話 ID を渡さないが、シェルには渡す（実機で確認） |
| D-014 | 2026-10-31 | 通信の仕組みは全員対等（ピアツーピアのメッセージバス）とし、統括を立てる運用は使い方の例として位置づける | 仕様書 §要件「通信経路を統括の中継に限定しない」。統括中心の仕組み（仕事の管理・権限）は今後の検討（ROADMAP） |
| D-015 | 2026-10-31 | ドキュメントは「現行」と「履歴（`docs/archive/`）」に分け、食い違いはコードを正とする | 新しいセッションが古い設計を信じて誤った作業をしないようにするため |
| D-016 | 2026-11-02 | `channel_ack` をなくし、`channel_receive` で本文を返した時点で取得済みにする。通知に本文は入れない（D-002 は維持） | ユーザーの判断。受信・ACK・返信の3回の呼び出しを、受信・返信の2回に減らす。本文を通知に入れる案も検討したが、本文をツールの結果として受け取るほうが「ほかの AI からの連絡」として扱われやすく安全なので、今の形に ACK の省略だけを加えた。代わりに、受け取った直後にセッションが落ちたときの取り直しはできない |
| D-017 | 2026-11-02 | 参加者は役割の ID（`dev`・`planning` など）で識別する。ID の指定は必須（省略したら断り、ユーザーに尋ねさせる）。使用中でなければ、ハーネスが違っても同じ ID に入れる。Codex は会話 ID も必須。入れ替わりは自動で知らせない | ユーザーの判断。担当を Codex と Claude Code の間で入れ替えたいが、ID がハーネスに縛られていて入れ替えられず、受信箱も引き継げなかった。決定の一覧は [design/role-id-takeover-decisions.md](design/role-id-takeover-decisions.md) |
| D-018 | 2026-11-02 | **ルーム**を入れる。1つのセッションは同時に1つのルームにだけ入り、参加のときにルームを指定する。ID はルームごと。ルームの作成・削除・一覧は MCP ツールだけで行い、AI はユーザーに頼まれたときだけ作る・消す。ないルームへの参加は断り、ユーザーに尋ねさせる。削除は全員が退出してから（切断中も数え、登録だけの ID は数えない）。ルームの ID は英字・数字・`-`・`.`・`_` の1〜32文字で、大文字と小文字を区別する。移るときは退出してから参加する（再起動は要らない）。DB は新しいファイルにし、前のデータは引き継がない | ユーザーの判断。作業ごとに場所を分けたいが、チャンネルが1つしかなく、全員宛てや参加者の一覧が混ざっていた。決定の一覧は [design/rooms-decisions.md](design/rooms-decisions.md) |
| D-019 | 2026-11-02 | 実物のレビュー試験（統括 Codex と Claude のレビュアー2名）で出た指摘を直す。通知が失敗したら間隔を空けて送り直す。ID を引き継がれた・ルームを削除されたセッションは、理由を伝えて参加していない状態に戻す（自動では参加し直さない）。同じトークンファイルで2つ起動したら、先のほうが止まる。注意点（`client_message_id` の重なり、参加済みの join で変わらない項目、外部フォント）は、仕様どおりとして変えない | ユーザーの指示（レポートを元に、直すべきところを直す）。直さなかった注意点は ROADMAP の既知の問題 K-6〜K-8 |
| D-020 | 2026-11-02 | **Pi（pi-coding-agent）を、Codex・Claude Code と同じ機能・同じ使い方で参加させる**。ユーザーは mcp.json に session_mail を登録し（`exposure: "direct"`）、通知を受け取るだけの Pi 拡張機能（`integrations/pi/`）を入れる。ブリッジは、クライアント名 `pi` を Claude と同じ扱いにし、通知を Channel の代わりに拡張機能の受け口に書く。受け口の場所は Pi のプロセス番号で決める（受け渡しなし）。ブローカー・DB・WebUI は変えない（種類は「Claude」と表示される）。Codex・Claude にない機能（自動登録、退出・削除の確認など）は足さない | ユーザーの判断（Claude Code・Codex とまったく同じ機能にする）。Pi の MCP は、ログとツール一覧の変更以外の通知を捨てるので、Channel では届かない（ソースで確認）。設計は [design/pi-integration-design.md](design/pi-integration-design.md)、試験の記録は [verification/pi-20261102.md](verification/pi-20261102.md) |
| D-021 | 2026-11-02 | 既知の問題のうち、直せるが直すかを決める必要があったものを決めた。K-8（WebUI が Google のフォントを読み込む）は直す：外のフォントをやめ、CSP でも外のオリジンを許さない。K-5（`viewer-token --rotate` にはブローカーの停止が要る）・K-9（Pi の `/new` などのあとは参加し直す）・K-11（Pi の種類が「Claude」と出る）・K-12（複数ユーザーの Linux での Pi の受け口）は直さない | ユーザーの判断（推奨どおり）。K-8 は小さな変更で外への通信がなくなる。K-5 はめったに使わず、止めればできる。K-9・K-11 は D-020（Codex・Claude にない機能は足さない、DB は変えない）のとおり。K-12 は1人で使う PC が前提 |
