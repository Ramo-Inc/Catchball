# 検証記録：Pi（pi-coding-agent）の参加と自動受信（2026-11-02）

> この記録は、**記録した時点の版**（D-020 を実装した直後の `main`）のものです。

- 対象：`@earendil-works/pi-coding-agent` 1.5.0、モデルは Claude Haiku（`claude-haiku-5-5`。料金を抑えるため）
- 環境：Linux（クラウドの作業環境）。ブローカー・Pi の設定・データは一時フォルダーに置いた
- 進め方：Pi は RPC モードで起動したままにし、試験の手順を自動で送った（RPC は試験を自動で進めるために使っただけで、対象は TUI のセッション）。相手役は `session-mail` CLI
- 再通知の間隔：試験用のブローカーだけ、Claude の再通知（`notify.claude_renotify_backoff_ms`）を 20 秒にした（既定は 5・15・30 分）
- 登録と導入は、OPERATIONS §2 の手順のとおり：
  - `mcp.json` に session_mail（`command: "node"`、`exposure: "direct"`）
  - `pi install <Catchball>/integrations/pi`

## 結果

| # | 確かめたこと | 結果 |
|---|---|---|
| 1 | 参加すると、確認用の通知で Pi が自分から動き、「確認済み」になる | ✅ 参加の約 8 秒後に、プロンプトなしで動き出し、`channel_receive` を呼んだ。`自動受信:verified` |
| 2 | 相手から送ると、Pi が自分から受信して返信する | ✅ 新着の 5 秒後に動き出し、受信して、reply_to 付きで返信した。相手役が受け取った |
| 3 | 作業中に届いたものは、作業のあとに処理される | ✅ `sleep 20` の作業中に送った。作業の答え（「作業1 完了」）のすぐあとに通知が入り、受信と返信をした |
| 4 | Esc（中断）のあとも、再通知で受信される | ✅ 通知が Pi の中で待っているあいだに中断した。中断の直後は未取得が1件残った。再通知（試験では 20 秒）で動き出し、受信した |
| 5 | `/new` のあと、同じ ID で参加し直すと、未取得の通知が届く | ✅ `/new` の直後は `offline`（ブリッジが起動し直したため）。そのあいだに送った1件は、参加し直した直後に通知されて受信された |
| 6 | 退出 | ✅ `channel_leave` で退出した |

LLM の実行は、合計 8 回でした。

## 気づいたこと

- 試験 3 で、Pi は最初の返信の `client_message_id` に日本語を使って断られ、英数字に直して送り直した。今の入力の検証どおりの動き（Codex・Claude と同じ）。
- 試験 4 のとおり、中断すると Pi の中で待っていた通知は流れる。今の再通知のしくみ（既定は 5 分後）で受信される。
- WebUI と `status` では、Pi の種類は「Claude」と出る（設計どおり）。
