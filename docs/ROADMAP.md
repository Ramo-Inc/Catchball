# 今後の作業と既知の問題（v1.0.0-alpha.1 時点）

優先度の高い順に並べています。着手したら、この文書と [REQUIREMENTS.md](REQUIREMENTS.md) を更新してください。

## 1. ベータ版に向けて必要なこと

| # | 作業 | 内容 | 関係する要件 |
|---|---|---|---|
| R-1 | Windows での動作確認 | インストール、ブローカーの起動、Codex の実体のパス（`codex.command`）、PowerShell からの起動、ファイアウォール、別の PC からの WebUI | 運用の前提 |
| R-2 | 既存の5セッションでの目的達成試験 | ユーザーの実際の環境で、仕様書 §12.2 の全段階を確かめる。ユーザーとの対話から始め、2つ目の課題（継続利用）まで行う。証跡は `docs/verification/` に残す | §12.2・§12.3 |
| R-3 | 実物での機能試験の残り | 個別送信の全20方向（`admin export` で集計）、実物のセッションを切断して回復させる、ブローカーを強制終了した後に受付済みの投稿が残るか | §12.1 |
| R-4 | 承認待ち・中断の検知 | Claude と Codex の `PermissionRequest`・`Stop`・`UserPromptSubmit`・`Interrupt` などのフックから `POST /api/agent/activity` を呼び、WebUI に「承認待ち」「中断後のため停止中」を出す。フックは**何も出力せずに終わる**こと（承認の判断に関わらないため）。API は実装済み | §8・§9 |

## 2. 検討中の機能

| # | 機能 | 内容 |
|---|---|---|
| F-1 | 統括を中心にした使い方の支援 | ① 仕事（担当・受入条件・状態）をシステムで扱う ② 担当どうしのやり取りの写しを統括へ自動で送る（禁止・写し・自由から選べる） ③ WebUI に仕事のボード（割当済み → 作業中 → 質問・障害 → 完了報告 → 受入済み） ④ 統括だけに許す操作（割り当て・受入）。将来の構造化のため、`messages.ext_json` を空けてある |
| F-2 | 別の PC のセッションの参加 | ブリッジが自分の PC で `codex queue` を実行する形にすれば、Codex も含めて別の PC から参加できる。ブローカーへの接続は SSH のトンネル（`ssh -L 47821:127.0.0.1:47821`）が安全 |
| F-3 | Claude の通知の遅れを短くする | 今は、ハートビート（5 秒ごと）を待つので最大で 5 秒遅れる。long-poll にすれば短くできる |

## 3. 既知の問題

| # | 症状 | 影響 | 回避策 |
|---|---|---|---|
| K-1 | Codex が自分のターンの中で受信を済ませても、先に出した `codex queue` の通知がキューに残り、後で「0件」の短いターン（約3秒）が走る | 小（害はないが、統括の画面に空のターンが出る） | 直前にツールを使っていた Codex への通知を 8 秒待たせて減らしている（`codex_quiet_after_tool_ms`）。完全にはなくならない |
| K-2 | Esc で中断した直後の Codex は、届いた通知を自動では処理しない | 中 | 何か入力すれば、そのターンの後で処理される。R-4 で画面に表示する予定 |
| K-3 | Claude の開発用 Channel は、起動のたびに確認画面が出る | 小 | 「I am using this for local development」を選ぶ。Channel は Anthropic のプレビュー機能で、自作の Channel は許可リストに入っていないため |
| K-4 | MCP サーバーは、起動中のセッションには後から追加できない（Codex・Claude とも） | 小 | 登録してから起動する。登録より前に起動したセッションは、一度だけ再起動する |
| K-5 | 管理用 CLI の `provision` と `viewer-token --rotate` は、ブローカーを止めないと DB を開けない | 小 | ブローカーの起動中は、`provision` は管理用の API を通るので動く。`viewer-token --rotate` はブローカーを止めて実行する |
