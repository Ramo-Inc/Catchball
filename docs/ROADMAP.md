## 1. ベータ版に向けて必要なこと

| # | 作業 | 内容 | 関係する要件 |

| R-1 | Windows・Mac での動作確認 | インストール、ブローカーの起動、Codex の実体のパス（`codex.command`）、PowerShell からの起動、ファイアウォール、別の PC からの WebUI、ルームごとのトークンファイルのフォルダー名（大文字・ドットの置き換え）。Pi では、受け口（Windows は名前付きパイプ `\\.\pipe\catchball-pi-<番号>`、Mac は `$TMPDIR` の Unix ソケット）と、ブリッジの親のプロセス番号が Pi と一致するか（Node のバージョン管理の道具を使う場合も） | 運用の前提 |

| R-3 | 実物での機能試験の残り | 個別送信の全20方向（`admin export` で集計）、実物のセッションを切断して回復させる、ブローカーを強制終了した後に受付済みの投稿が残るか、ID を引き継がれたセッションが実物の CLI で参加し直せるか（自動試験では確認済み） | §12.1 |
| R-4 | 承認待ち・中断の検知 | Claude と Codex（Pi は対象外。Pi で入れるなら拡張機能のイベントから呼ぶ）の `PermissionRequest`・`Stop`・`UserPromptSubmit`・`Interrupt` などのフックから `POST /api/agent/activity` を呼び、WebUI に「承認待ち」「中断後のため停止中」を出す。フックは**何も出力せずに終わる**こと（承認の判断に関わらないため）。API は実装済み | §8・§9 |

## 2. 検討中の機能

| # | 機能 | 内容 |
|---|---|---|
| F-1 | 統括を中心にした使い方の支援 | ① 仕事（担当・受入条件・状態）をシステムで扱う ② 担当どうしのやり取りの写しを統括へ自動で送る（禁止・写し・自由から選べる） ③ WebUI に仕事のボード（割当済み → 作業中 → 質問・障害 → 完了報告 → 受入済み） ④ 統括だけに許す操作（割り当て・受入）。将来の構造化のため、`messages.ext_json` を空けてある |
| F-2 | 別の PC のセッションの参加 | ブリッジが自分の PC で `codex queue` を実行する形にすれば、Codex も含めて別の PC から参加できる。ブローカーへの接続は SSH のトンネル（`ssh -L 47821:127.0.0.1:47821`）が安全 |
| F-3 | Claude・Pi の通知の遅れを短くする | 今は、ハートビート（5 秒ごと）を待つので最大で 5 秒遅れる。long-poll にすれば短くできる |
| F-4 | ルームの退出済みの記録の扱い | 退出で配送を止めたメッセージは、ルームを削除するまで WebUI に「× 退出で配送停止」として残る。ユーザーの元の言葉は「削除」だったので、記録も消す必要があればユーザーに確認して直す（[design/role-id-takeover-decisions.md](design/role-id-takeover-decisions.md) の 10 の補足） |

## 3. 既知の問題

| # | 症状 | 影響 | 回避策 |
|---|---|---|---|
| K-1 | Codex が自分のターンの中で受信を済ませても、先に出した `codex queue` の通知がキューに残り、後で「0件」の短いターン（約3秒）が走る | 小（害はないが、統括の画面に空のターンが出る） | 直前にツールを使っていた Codex への通知を 8 秒待たせて減らしている（`codex_quiet_after_tool_ms`）。完全にはなくならない |
| K-2 | Esc で中断した直後の Codex は、届いた通知を自動では処理しない | 中 | 何か入力すれば、そのターンの後で処理される。R-4 で画面に表示する予定 |
| K-3 | Claude の開発用 Channel は、起動のたびに確認画面が出る | 小 | 「I am using this for local development」を選ぶ。Channel は Anthropic のプレビュー機能で、自作の Channel は許可リストに入っていないため |
| K-4 | MCP サーバーは、起動中のセッションには後から追加できない（Codex・Claude とも） | 小 | 登録してから起動する。登録より前に起動したセッションは、一度だけ再起動する。Pi は `/reload` でも読み込み直せる |
| K-5 | 管理用 CLI の `viewer-token --rotate` は、ブローカーを止めないと DB を開けない | 小 | ブローカーを止めて実行する（`provision` は、ブローカーの起動中は管理用の API を通るので動く） |
| K-6 | 担当を引き継いだ新しいセッションが、前の担当と同じ `client_message_id` を使うと、前の送信の結果が返る（または `IDEMPOTENCY_CONFLICT`） | 小 | 送信ごとに一意な値を使う（運用指示と MCP_TOOLS に書いてある）。仕様どおりの動き |
| K-7 | 参加済みのセッションでもう一度 `channel_join` しても、`coordinator` と `conversation_id` は変わらない | 小 | 表示名と役割だけが変わる（ツールの説明に書いてある）。変えたいときは、退出してから参加し直す |
| K-8 | WebUI は Google Fonts を読み込むので、開いたときに外部へ要求が出る | 小 | 外部への要求を避けたいなら、`src/web/index.html` のフォントの行を消す（文字はシステムのフォントで出る） |
| K-9 | Pi の `/new`・`/resume`・fork・`/reload` で、Pi がブリッジを起動し直すので、ルームに参加していない状態に戻る | 中 | 同じルーム・同じ ID で参加し直すよう頼む。未取得は残り、参加し直すとすぐ通知される（[PI_SETUP.md](PI_SETUP.md) §7） |
| K-10 | Esc で中断すると、Pi の中で待っていた通知が流れる | 小 | 再通知（既定は5分後）で受信される。急ぐなら「受信して」と頼む |
| K-11 | WebUI と `status` で、Pi の種類が「Claude」（`claude`）と出る | 小 | 表示名で見分ける。直すには DB の変更が要るので、D-020 で見送った |
| K-12 | 複数のユーザーが使う Linux では、ほかのユーザーが先に同じ名前の Pi の受け口を作ると、通知が届かないか、通知文（本文なし）が渡ることがある | 小 | 1人で使う PC が前提（[ARCHITECTURE.md](ARCHITECTURE.md) §7） |
