# 決定事項：役割の ID と担当の入れ替え

ユーザーとの質疑（2026-11-02）で決まった内容です。この文書が前提で、[仕様書（role-id-takeover.md）](role-id-takeover.md) はこれを実装に落としたものです。**ここに書いた決定は、ユーザーの指示なしに変えない。**

## やりたいこと

- 担当（例：開発）を、Codex から Claude Code へ、またはその逆へ入れ替えられるようにする。
- 参加者は `dev`・`planning` のような**役割の ID だけで識別する**。Codex か Claude か（ハーネス）は関係ない。
- いちばん簡単な形にする。余計な仕組みは作らない。

## 決まったこと

| # | 項目 | 決定 | 仕様書 |
|---|---|---|---|
| 1 | 参加の条件 | その ID を使っているセッションがいなければ（切断中・退出済み・未参加）、どのハーネスからでも参加できる | §4.1 |
| 2 | 入れ替えのやり方 | 新しいセッションに「ID は dev で参加して」と頼むだけ。ID が空いていれば入れる | §2・§4.7 |
| 3 | 引き継ぐもの | サーバー側で特別なことはしない。残っている未取得のメッセージは、新しいセッションがそのまま受け取る | §4.1 |
| 4 | ハーネスの表示 | 参加者の欄に今のハーネスを表示するのは、そのまま残す。メッセージごとの記録は追加しない | §4.4 |
| 5 | ID の省略 | 認めない。断って、ユーザーに ID を尋ねさせる | §4.1・§4.2 |
| 6 | 足りない指定 | 参加に必要なものが足りなければ断る。Codex の会話 ID がない参加も断る | §4.1 |
| 7 | ID が使用中のとき | 断る。別の ID には逃げさせず、ユーザーに確認させる | §4.1 |
| 8 | 入れ替わりの知らせ | しない。引き継ぎはセッションどうしで行う | §2・§6 |
| 9 | 切断中の相手 | 送れる。戻った（または同じ ID で入った）セッションが、未取得のメッセージを読める | §4.1 |
| 10 | 退出 | 明示的に退出させたら、残りのメッセージは届けない。退出した ID や存在しない ID への送信はエラー。退出した ID でも、同じ ID で参加し直せる | §4.1 |
| 11 | 今の ID | `codex-main` などは、いじらない。古いものは古いものとして、そのまま置いておく | §4.6 |
| 12 | 固まったセッション | 仕組みは作らない。前のセッションが完全に終了したことを人が確かめてから参加する。見分け方と対処は「異常検知と異常処理」として文書にまとめる | §4.7・§6 |
| 13 | 異常時の文書 | 今の内容（ブローカーの再起動、停電、止まっている間の送信）と 12 を、1つの節にまとめる | §4.7 |
| 14 | ID の付け方 | ドキュメントを用意し、読めば分かるようにする | §4.7 |

**10 の補足**：ユーザーの言葉は「残りのメッセージは削除」。今の作りでは、退出すると残りのメッセージは「退出で配送停止」になり、二度と届かない。WebUI には「× 退出で配送停止」の記録が残る。仕様書はこの今の作りのままとしている。記録も消す必要があれば、ユーザーに確認して直す。

## 決定を正しく動かすための実装上の注意

決定は変えません。コードと噛み合わせるための注意です。

- **会話 ID の扱い**：会話 ID は、その参加で指定されたものだけを使う。今のコードは前の値を残すので、入れ替えたときに通知が前の会話に届いてしまうため（§4.1）。
- **参加済みのセッションで別の ID を指定したら断る**：今のブリッジは、参加済みのときに `agent_id` を黙って無視するため（§4.2）。
- **参加の処理は1つのトランザクションで行い、参加した時点から使用中として扱う**：決定7の「使用中なら断る」を確実にするため。表示名の重複で断ったときは何も残さない（§4.1）。
- **ドキュメントの試験**：会話の中から参加する方法のブリッジでも確かめる（§5）。
